TRABAJAR CON CLAUDE

Recibir el proyecto

La web vive completa en un repositorio de GitHub: código, assets, documentación y esta misma librería. Así es como se consigue y cómo dejarlo funcionando en tu ordenador — solo hace falta hacerlo una vez.

1

Pide acceso al repositorio

El proyecto está en github.com/unaiarambarri/neety (privado). Necesitas una cuenta de GitHub y que te inviten como colaborador con permiso de escritura. Si no vas a usar GitHub, también puede llegarte como zip (unos MB; con los assets originales, por WeTransfer o Drive): el contenido es el mismo y los pasos siguientes no cambian.

2

Tráelo a tu ordenador

Con Ship Studio: «Importar proyecto» y elige el repositorio de GitHub (o la carpeta del zip); él se encarga de clonarlo e instalar lo necesario. Con terminal: git clone https://github.com/unaiarambarri/neety.git. Con zip: descomprímelo (doble click en Mac, «Extraer todo…» en Windows). En los tres casos obtienes una carpeta neety/ que ya es la web.

3

Instala lo necesario (solo la primera vez)

Necesitas Node 20 o superior (gratis, de nodejs.org). Después, en un terminal dentro de la carpeta, ejecuta npm install (~1 minuto): regenera las dependencias, que no viajan ni en el repo ni en el zip. Si has importado con Ship Studio, este paso ya está hecho.

4

Crea tu .env.local con tu token de Sanity

Blog, eventos, academia y el equipo se leen de Sanity, y la clave para leerlos está fuera del repositorio a propósito. En la carpeta del proyecto, copia .env.example como .env.local y rellena SANITY_READ_TOKEN. El token lo genera cada persona con su cuenta (no se comparte por chat): sanity.io/manage → proyecto Neety → API → Tokens → Add API token, permiso Viewer. Hace falta ser miembro del proyecto; si no lo eres, pide la invitación. Sin este archivo la web arranca pero esas páginas fallan con «Faltan SANITY_PROJECT_ID / SANITY_READ_TOKEN». Se lee solo al arrancar: si lo creas con el servidor abierto, reinícialo. Empieza por punto, así que el Finder lo oculta (Cmd + Shift + . para verlo).

5

Ya está — conecta con Claude

Con la carpeta preparada, sigue los pasos de la sección siguiente, «Conectar con Claude». Estas mismas instrucciones están en el archivo README.md del proyecto, por si las necesitas sin conexión.

¿Tienes que pasar el proyecto a alguien sin GitHub? El comando exacto para preparar el zip (qué carpetas excluir y por qué) está en README.md → «Si eres quien prepara el zip» — o pídeselo a Claude: «prepara el zip del proyecto para enviarlo».

TRABAJAR CON CLAUDE

Conectar con Claude

La web se mantiene conversando con Claude: tú pides los cambios en castellano y él toca el código por ti. No hace falta saber programar. Puedes conectar de varias formas según la herramienta con la que trabajes.

¿Trabajas con Ship Studio? No hay nada que configurar

Si abres el proyecto en Ship Studio, Claude y el preview ya vienen conectados: escribes la petición en el chat, ves el cambio en vivo en el panel de al lado y publicas desde ahí. Los cinco pasos de abajo son para trabajar fuera de Ship Studio: con la app de Claude (la misma del chat) o con Claude Code en el terminal, sobre la carpeta del proyecto.
1

Abre la app de Claude

La app de escritorio de Claude (Mac/Windows) — la misma con la que chateas — tiene una sección «Code» para trabajar sobre proyectos. Se descarga en claude.com/download. Si prefieres el terminal, el comando claude (Claude Code) hace lo mismo.

2

Abre la carpeta del proyecto en «Code»

Elige la carpeta neety/. A partir de ahí es un chat como el de siempre, con una diferencia: Claude puede leer y editar los archivos de la web. Además lee automáticamente las instrucciones del proyecto (CLAUDE.md), así que ya conoce el stack, los colores y las convenciones — no hace falta explicarle nada.

3

Arranca el preview

Pídele «arranca el servidor de desarrollo» y abre http://localhost:3000 en el navegador: ahí verás cada cambio en vivo antes de publicarlo. Esta librería vive en /library.

4

Pide el cambio

En castellano, como a un compañero: qué quieres, dónde va y el resultado esperado. Los tres tipos de petición habituales —contenido, componentes, secciones nuevas— van justo debajo con ejemplos para copiar.

5

Revisa y publica

Comprueba el cambio en el preview y, cuando esté bien, dile «despliega la web»: Claude ejecuta el script de publicación y el cambio queda en producción en unos minutos.

Ojo: el chat corriente de claude.ai (sin la sección «Code») no puede tocar el proyecto. Úsalo si quieres para pensar textos o preparar contenidos, y luego trae aquí el resultado: «cambia el titular del hero por este que he preparado: […]».

IDIOMAS (ESPAÑOL / INGLÉS)

La web es bilingüe desde el 27-ago-2026: el español vive en la raíz y el inglés bajo /en con las URLs traducidas (/en/platform, /en/use-cases/…). Cada texto existe en los dos idiomas en el mismo sitio (un objeto copy({ es, en }) junto a la sección), así que un cambio de copy se pide para uno o para los dos. El selector del footer salta a la misma página en el otro idioma, y quien entra en la portada desde fuera de España aterriza en inglés (solo España se queda en español). El blog y el equipo se traducen en el Studio de Sanity: cada artículo tiene su versión ES y EN enlazadas.

TRABAJAR CON CLAUDE

Editar el blog y el equipo (Sanity)

El blog y el equipo de «Sobre Neety» no viven en el código: viven en un gestor de contenidos (Sanity) con su propio panel, el Studio, en neety.sanity.studio. Se entra con la cuenta con la que os hayamos invitado. Todo lo demás de la web (textos de las páginas, imágenes, secciones) sigue siendo cosa de Claude.

Escribir un artículo entero por ti a partir de un texto o una idea: lo deja como borrador en el Studio (ver abajo).
AÑADIR UN ARTÍCULO PIDIÉNDOSELO A CLAUDE

Es la vía rápida si no os apetece pelearos con el editor: le pasáis a Claude el texto (o el tema) y la imagen, y Claude deja el artículo como borrador en el Studio. Claude nunca publica: publicáis vosotros después de leerlo, con el botón «Publish» de siempre. Por debajo usa studio/scripts/new-post.mjs, que convierte un Markdown en un artículo con todos sus campos.

QUÉ NECESITA CLAUDE DE VOSOTROS

El texto (pegado, en un .docx/.md, o solo el tema y los puntos clave si queréis que lo redacte él).
La imagen principal: un PNG o JPG grande (mínimo 1208 × 768, mejor 2400 de ancho). AVIF no vale. Si va dentro del artículo alguna figura más, también.
Etiquetas (de las que ya existen en el Studio; la primera es la principal) y firma (un miembro del equipo; «Equipo Neety» para firmar como empresa). Si no lo decís, Claude os pregunta o os enseña las que hay.
Opcional: fecha, entradilla, versión en inglés.

QUÉ HACE CLAUDE

Redacta o adapta el texto a las piezas que tienen diseño: titulares de sección, párrafos, listas, citas y figuras con pie. Escribe la entradilla corta de las cards y la larga de la ficha.
Comprueba que las etiquetas y la firma existen y que no hay otro artículo con la misma URL.
Sube la imagen y crea el borrador en el Studio.
Os pasa el enlace para revisarlo. Vosotros retocáis lo que queráis y le dais a «Publish».

EJEMPLO DE PETICIÓN

«Crea un artículo para el blog con este texto: [pegar]. La imagen principal es ~/Desktop/portada-leads.png (se ve un panel con señales de compra). Etiquetas: Sales, AI Agent. Firma: Equipo Neety. Déjalo como borrador en Sanity.»

Para el inglés, después de publicar el español: «Haz la versión en inglés del artículo «X» y déjala como borrador enlazada con el español». Claude la crea ya enlazada (menú «Translations» del Studio), igual que si la hubierais creado a mano.

Para que funcione, en el ordenador desde el que trabajáis con Claude hay que haber entrado una vez en Sanity desde la terminal (cd studio && npx sanity login, con la misma cuenta del Studio). Claude os lo indica si falta.

PUBLICAR: QUÉ PASA AL DARLE AL BOTÓN
Guardar no publica. Mientras editas, el Studio guarda un borrador solo; la web no lo ve. Puedes dejar un artículo a medias sin miedo.
«Publish» lo hace visible y dispara solo la reconstrucción de la web: en unos 2 minutos está publicado. No hay que avisar a nadie ni hacer nada más.
Mientras neety.com esté en modo «próximamente», el blog no sale en la web pública: se revisa en la copia de revisión (hoy neety.treseiscero.app; después, el subdominio de prueba de Neety), que es la que se reconstruye con cada «Publish». Sacar el blog en neety.com es una decisión (se le pide a Claude), no un botón del Studio; a partir de ese día, «Publish» actualiza neety.com directamente.
«Unpublish» lo retira de la web (también en ~2 min). Borrar un artículo lo elimina del todo; para quitarlo temporalmente, mejor «Unpublish».

Si no aparece: ¿le diste a Publish (no solo a guardar)? ¿han pasado 2 minutos? ¿está el blog ya publicado en neety.com o sigue solo en la copia de revisión? Si todo eso está bien, pídeselo a Claude: «El artículo «X» está publicado en Sanity pero no sale en la web».

ESCRIBIR UN ARTÍCULO: CAMPO A CAMPO
CAMPO	PAUTA
Título	Una línea. En las cards se corta a dos.
Slug (URL)	Se genera solo desde el título («Generate»). No lo cambies una vez publicado: es la dirección del artículo y rompería los enlaces compartidos.
Entradilla	El resumen de las cards. Máximo ~160 caracteres: por encima se corta a tres líneas.
Imagen principal	Sube el original grande (mínimo 1208 × 768, mejor 2400 de ancho): la web la recorta sola al tamaño de cada hueco. Con el punto de interés (hotspot) eliges qué parte no se debe recortar. El texto alternativo es obligatorio: describe qué se ve.
Etiquetas	La primera es la principal (la única que se ve en la card). Una etiqueta nueva aparece sola en el filtro del blog; créala en «Etiqueta» antes de usarla.
Firma	Un miembro del equipo. Para firmar como empresa, «Equipo Neety». Si falta alguien, créalo en «Miembro del equipo» (y desmarca «Mostrar en Sobre Neety» si no debe salir en el grid).
Fecha	Ordena el listado (más reciente arriba) y se muestra en la ficha. Se puede poner una fecha pasada.
Entradilla del artículo	La de la cabecera de la ficha; más larga que la de las cards (2–3 frases). Si se deja vacía se usa la corta.
Imagen de portada de la ficha	Opcional. Si el artículo tiene arte propio, aquí; si no, la ficha reusa la imagen principal.
Minutos de lectura	Opcional: si se deja vacío se calcula solo.
Cuerpo	Solo hay cuatro piezas con diseño, y bastan: Titular de sección (cada uno abre un apartado y alimenta el índice lateral de la ficha — pon uno cada 3–5 párrafos), párrafos, lista, cita destacada y figura (imagen + texto alternativo + pie). Negrita y cursiva sí; no hay más estilos, a propósito.
Descripción para buscadores	Opcional, 1–2 frases. Si está vacía se usa la entradilla.
ESPAÑOL E INGLÉS DENTRO DEL STUDIO

La web tiene dos versiones (español en neety.com/…, inglés en neety.com/en/…) y cada una lee del Studio solo lo que está en su idioma. No hay traducción automática: lo que no exista en inglés, no sale en inglés.

UN DOCUMENTO POR IDIOMA

Artículos: cada idioma es un artículo aparte, con su título, su slug y su texto.
Portada del blog: una ES y otra EN («Portada del blog (ES)» / «(EN)»), cada una con sus destacados.

COMPARTIDO POR LOS DOS IDIOMAS

Etiquetas: un solo nombre, en inglés («AI Agent», «Sales»…), el mismo en las dos webs.
Equipo (y firmas): un solo documento; el nombre es igual y el puesto tiene un campo «(inglés)» al lado.
Escribe primero el artículo en español y publícalo (o déjalo en borrador).
Crea el inglés desde el propio artículo: arriba, menú «Translations» → «English» → «Create». Eso crea el artículo EN ya enlazado con el español. No lo crees como artículo nuevo suelto: quedaría sin enlazar (ver abajo por qué importa).
Rellena el EN: título, entradilla, cuerpo y descripción para buscadores, en inglés. El slug se genera desde el título inglés (una URL distinta, /en/blog/…). La imagen principal se puede reutilizar tal cual; el texto alternativo va en inglés.
Publica el EN. Hasta entonces, el artículo solo sale en la web en español y el selector de idioma lleva al listado inglés del blog.

Por qué importa el enlace: es lo que hace que el botón de idioma de la ficha salte a ese mismo artículo en el otro idioma, y lo que le dice a Google que las dos URLs son el mismo contenido (etiquetas hreflang), para que muestre a cada visitante la versión de su idioma en vez de tratarlas como duplicados. Se traduce a mano o se le pide a Claude («traduce al inglés el artículo «X»»): lo redacta y lo deja ya enlazado.

PORTADA DEL BLOG Y EQUIPO

Portada del blog

Un documento por idioma con el artículo destacado (la card grande) y exactamente 4 para la lista de al lado, en el orden en que se ven. Si no está configurado, la web pone el más reciente y los cuatro siguientes.

Toda sección de la home usa la misma escala de padding vertical en su <section> raíz: py-12 md:py-16 lg:py-28. Como cada sección lleva padding arriba y abajo, el hueco real entre secciones es la suma: 96px en móvil, 128px en tablet y 224px en desktop (el valor del diseño).

La banda asoma 24/32px por encima del origen sticky (-top + altura extra): su borde superior nunca entra en el viewport y los fundidos de entrada/salida no pueden enseñar un corte.
BottomBlur solo existe con puntero fino (pointer-fine:block): en táctil la barra inferior del navegador (Safari iOS) lo hacía leerse como un corte sobre la web.

MANTENIMIENTO

Mantenimiento técnico

Referencia para cambios que tocan la base del sistema (para perfiles más técnicos o para Claude).

Cambiar colores, tipografía o espaciado: edita el bloque @theme en app/globals.css. Toda la web y esta librería se actualizan solas.
Añadir un componente reutilizable: créalo en components/ y añádelo a la sección «Componentes de la web» (components/library/catalog.tsx) para que quede documentado.
Idiomas: todo texto visible va en copy({ es, en }) (lib/i18n.ts); una página nueva es un components/pages/XPage.tsx con lang más dos rutas finas (app/(es) y app/(en)/en) con alternates() en la metadata — sin hreflang el selector del footer no sabe saltar. Auto-routing por país en functions/_middleware.ts. Ver decisión 2026-08-27 · i18n.
CMS (Sanity): el esquema vive en studio/schemaTypes/; tras cambiarlo, npx sanity deploy desde studio/. La web lo lee en build por components/blog/data.ts y components/sobre/team.ts (las secciones no saben de Sanity). Publicar en el Studio → webhook → GitHub Actions → copia de revisión; producción solo a mano desde Actions. Tokens de CI en los secretos del repo; en local, cada persona con el suyo en .env.local (ver «Recibir el proyecto»). Plan y estado: docs/cms-sanity.md.
Tomar una decisión no obvia: anótala en docs/decisiones.md con su porqué.
Validar: npx tsc --noEmit. No ejecutar npm run build con el dev server de Ship Studio activo.
Desplegar: cada push a main actualiza solo la copia de revisión (GitHub Actions). Producción (neety.com) siempre a mano: Actions → «Deploy» → Run workflow → prod, o ./scripts/deploy.sh prod desde el terminal. Detalles en CLAUDE.md §Deploy; lista de lanzamiento en docs/lanzamiento.md.
